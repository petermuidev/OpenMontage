# Media Transformation Catalogue V2 — Action Plan

The goal is a reliable director workflow that can inspect a reference or
authorized source, propose several truthful transformations, build the selected
one with existing tools, and transfer the method to another LLM agent without
private coaching.

## Phase 1 — Decision architecture

Status: implemented.

- Seven source-transformation kernels.
- Ten story/audio treatments.
- Six delivery profiles.
- Reject-by-default compatibility matrix.
- Schema-valid three-route transformation proposal.
- Router skill that separates reference signals from authorized source media.
- Draft recipes remain outside the proven catalogue.

## Phase 2 — Deterministic proof ladder

Prove the widest, cheapest local routes first:

1. Vibe-music slideshow from approved extracted frames.
2. Motivational narrated slideshow with sentence-to-scene evidence.
3. Factual multilingual venue tour with claim-to-scene evidence.
4. Truthful source-video recut with human/text exclusion intervals.
5. Full-frame clean recaption with subtitle blur or replacement.

Each proof follows:

```text
portable blueprint
→ architect proof
→ independent review
→ clean-room worker reproduction on different media
→ independent review
→ owner acceptance
→ proven catalogue
```

A technical render is not a proof. A failed proof remains in a dated audit and
may not be used as a creative baseline.

## Phase 3 — Controlled generative extensions

Only after the deterministic routes are reliable:

1. Clean-frame I2V for stills that genuinely need motion.
2. Multi-angle I2V with geometry and identity continuity checks.
3. Image cleanup or object removal before I2V, never as documentary invention.
4. Localized narration and dubbing with sentence-to-scene alignment.

Every provider call remains visible, cost-capped, owner-approved, and replaceable
by a named fallback. Generated scenery, rooms, views, people, facilities, and
conditions may not be presented as real operator evidence.

## Phase 4 — Director interface

After at least three independently reproduced recipes, add one thin interface
around the existing tools:

```text
analyze <url-or-path>
→ inventory and rights state
→ three transformation routes
→ owner selection
→ project scaffold
→ existing pipeline/tool execution
→ QA and evidence package
```

This interface must not become a new media engine. It invokes OpenMontage,
HyperFrames, FFmpeg, CRV, approved image editing, TTS, and provider adapters
through their existing ownership boundaries.

## Definition of a reproducible recipe

- Another agent receives no private prompt, HTML, or timeline from the architect.
- It selects frames and adapts story/design from the new source.
- It produces every required canonical artifact.
- Its candidate passes objective QA and full-playback creative review.
- It uses no more than one correction render.
- An independent reviewer classifies any failure by recipe, worker, source,
  provider, composition tooling, or QA tooling.
